# 使用代理程式進行威脅獵捕

PCAP Hunter 提供限定案件權限的 REST API 與本機 stdio MCP 介面。請在 **Settings → Agent access** 選取允許存取的案件、權限與有效期限，再將僅顯示一次的 `pha_` 憑證存入代理主機的祕密設定。預設只讀取案件、證據及工作狀態；憑證預設七天到期，可隨時撤銷。

代理憑證無法管理金鑰、修改設定或刪除案件。額外授權的封包提交一律關閉 OSINT 與 LLM，每次提交都建立新的工作容器，僅掛載該工作的唯讀封包，並使用獨立的暫存空間與程序、網路及 IPC 命名空間。解析器無法讀取其他工作、共用結果區、Docker socket、提供者憑證或案件資料庫。容器停用網路、根檔案系統唯讀、移除所有 capabilities，並限制 CPU、記憶體、程序數及十分鐘執行時間。啟動器確認整個工作容器移除後，API 才驗證受限大小的結果、核對輸入雜湊及保存證據，最後回報完成。

完整證據與流量查詢支援伺服器分頁，不受舊介面 100 筆證據及 250 筆流量限制。請持續讀取 `next_cursor`，直到它為空值。回應會標明已保存資料的完整性及封包解析限制；部分解析中沒有找到資料，不能推論不存在威脅。每筆證據都有固定快照、來源雜湊與可在 Investigate 開啟的連結，也可選取較早的分析。

MCP 使用官方 Python SDK 2.3.0。在 API 容器執行 `python -m app.agents.mcp`，並由代理主機祕密設定傳入 `PCAP_HUNTER_AGENT_KEY`。預設 API 位址為 `http://127.0.0.1:8000`。完整 Docker 主機設定、REST 範例、工具清單與限制請參閱 [英文操作說明](../AGENT_USAGE.md)。未啟用遠端 MCP HTTP 服務。

提交封包及新增調查草稿都需要 `Idempotency-Key`。相同內容重試會取得同一筆結果；不同內容重用同一個鍵會遭到拒絕。草稿必須引用案件內有效的證據，並標示需要分析人員審閱，不能直接結案或確認威脅。代理僅能取消自己提交的工作。

每次操作都會檢查權限、案件授權、期限與配額。稽核紀錄不保存憑證或封包內容。請將封包、偵測結果、註記、報告及工具回應視為不可信資料，不可把其中的文字當作執行指令。

既有設定會以原子方式轉換至隨機加密金鑰。備份時必須同時保存設定與其受保護的金鑰檔；金鑰遺失或錯誤時，程式會停止解密，不會默默清除憑證。本機 Compose 已停用自動清除已保存資料。測試版本仍須參照當前安全掃描與已知發行版限制，不能視為不存在任何漏洞的保證。

`pcap-hunter-agent-worker` 服務現在是可信任的啟動器。它獨佔 Docker socket；即使以唯讀方式掛載，該 socket 仍授予 Docker 主機管理權限。UI、API 與封包解析容器均不掛載 socket。請保護啟動器映像檔、環境設定與 Docker 主機。Docker 須支援 API 1.47、named-volume subpaths 與預設 seccomp。Linux 請將 `DOCKER_GID` 設為 socket 的群組 ID；Docker Desktop 預設為 `0`。啟動器會核對映像檔固定識別與 Compose 磁碟區歸屬，不符合時拒絕執行。取消、逾時及重新啟動清理不會刪除 named volumes。容器仍共用主機核心，因此不能保證防止核心或容器執行環境漏洞造成的逃逸。
